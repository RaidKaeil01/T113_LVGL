# T113-S3 重新烧录镜像后问题排查文档

## 🔍 问题现象

重新烧录全新镜像后，运行demo7程序出现**Segmentation fault（段错误）**，程序无法正常启动。

```bash
$ adb shell "cd /data && ./demo7"
wh=720x1424, vwh=720x2848, bpp=32, rotated=3
Turn on double buffering.
Turn on 2d hardware acceleration.
UI message queue initialized (capacity: 20)
Segmentation fault
```

---

## 📋 问题排查过程

### 1️⃣ **动态库依赖检查**

#### 问题1：libbz2.so.1.0 缺失

**错误信息：**
```
error while loading shared libraries: libbz2.so.1.0: cannot open shared object file
```

**排查方法：**
```bash
# 分析程序依赖
readelf -d demo7 | grep NEEDED

# 检查库文件
adb shell "ls -la /usr/lib/libbz2*"
```

**解决方案：**
```bash
# 推送bz2压缩库
adb push app_sdk/platform/t113/lib/libbz2.so.1.0 /usr/lib/
adb push app_sdk/platform/t113/lib/libbz2.so /usr/lib/
adb shell "chmod 755 /usr/lib/libbz2.so.1.0"
```

---

**错误信息：**

### 2️⃣ **字体文件缺失（根本原因）**

解决库文件问题后，程序仍然崩溃。通过调试发现**OTF字体文件缺失**才是根本原因。

#### 错误触发点

`main.c` 中的 `FONT_INIT()` 宏：
```c
#define FONT_INIT() \
    do { \
        add_font(FONT_TYPE_CN, FONT_TYPE_CN_PATH); \
        add_font(FONT_TYPE_CN_LIGHT, FONT_TYPE_CN_LIGHT_PATH); \
        add_font(FONT_TYPE_LETTER, FONT_TYPE_LETTER_PATH); \
        add_font(FONT_TYPE_LETTER_LIGHT, FONT_TYPE_LETTER_LIGHT_PATH); \
        add_font(FONT_TYPE_NUMBER, FONT_TYPE_NUMBER_PATH); \
    } while (0)
```

#### 排查方法

```bash
# 检查字体文件
adb shell "ls -la /usr/res/font/"

# 发现只有msyh.ttf，缺少OTF字体
-rwxr-xr-x    1 root     root       9751960 May 19  2023 msyh.ttf
```

#### 缺失文件清单

| 文件名 | 大小 | 用途 | 路径 |
|--------|------|------|------|
| `SOURCEHANSANSCN_REGULAR.OTF` | 8.0MB | 中文常规字体 | `/usr/res/font/` |
| `SOURCEHANSANSCN_LIGHT.OTF` | 7.9MB | 中文纤细字体 | `/usr/res/font/` |
| `Library-3-am-3.otf` | 33.9KB | 数字字体 | `/usr/res/font/` |
| `Aqum-2-Classic-2.otf` | 25.6KB | 装饰字体 | `/usr/res/font/` |

#### 解决方案

```bash
# 推送字体文件
cd app_sdk/build/app7
adb push res/font/*.OTF /usr/res/font/
adb push res/font/*.otf /usr/res/font/

# 验证字体文件
adb shell "ls -lah /usr/res/font/*.OTF /usr/res/font/*.otf"
```

**推送结果：**
```
-rw-rw-rw-    1 root     root       25.6K Dec 29  2025 /usr/res/font/Aqum-2-Classic-2.otf
-rw-rw-rw-    1 root     root       33.9K Dec 29  2025 /usr/res/font/Library-3-am-3.otf
-rw-rw-rw-    1 root     root        7.9M Dec 29  2025 /usr/res/font/SOURCEHANSANSCN_LIGHT.OTF
-rw-rw-rw-    1 root     root        8.0M Dec 29  2025 /usr/res/font/SOURCEHANSANSCN_REGULAR.OTF
```

## 📝 根本原因总结

### 主要原因：OTF字体文件缺失

**触发流程：**
1. `main.c` 中调用 `FONT_INIT()` 宏
2. `add_font()` 函数尝试加载OTF字体文件
3. FreeType库访问不存在的文件时触发**段错误**
4. 程序崩溃退出

**为什么旧镜像可以运行：**
- 旧镜像在 `/usr/res/font/` 目录包含完整的OTF字体文件
- 新镜像只包含 `msyh.ttf` (9.75MB)，缺少4个OTF字体

### 次要原因：动态库缺失

- `libbz2.so.1.0` - libcurl的bzip2压缩支持
- `libwpa_client.so` - WiFi管理客户端库
